# Singing practice on a phone — Prototype 15

Open the school site over HTTPS, sign in, choose a song's Vocals part, and tap **Play song**. On a phone this opens the focus view; it can also be opened before playback. White lyrics sweep yellow using the existing line timings, and the next two lines preview two musical bars before an entrance. **Pause / Continue**, **Try line again**, the song-position slider and **Skip to next vocal line** support short practice sessions. Retry/skip include a two-second lead-in and the song's count-in. Continue resumes without a new count-in. Teacher-led jam playback stays under teacher control.

Tap **Enable microphone** and allow the browser's microphone request to see **On pitch**, **Sing a little higher**, or **Sing a little lower**, alongside Target / You note names and a pitch meter. Headphones and one nearby voice give the clearest input. Lyrics/playback work without microphone permission. No microphone is opened on page load, and no audio is recorded, uploaded, persisted, or included in school/jam results. Feedback is practice guidance, not a saved grade. The microphone remains visibly on while paused, until switched off; changing the song/part/account/practice area, hiding/leaving the page, finishing the song, device loss or audio interruption releases it. A cancelled permission request also releases any stream that arrives later.

**Sound & pitch settings** contains music volume, metronome, comfortable/exact octave and microphone timing correction. Comfortable octave compares the melody's pitch class in the nearest octave to the student's voice; exact mode compares the written concert-pitch octave. The meter's green center allows ±35 cents. **Melody & sheet music** retains the existing staff and optional reference tones. Parts without selected melody notes remain lyrics-only and explain how a teacher can enable the guide. The original Full band warm-up now includes a simple vocal melody for trying the feature without school music.

## Implementation and limits

- `vocal-pitch.mjs` uses YIN-style normalized difference on a downsampled microphone waveform, with a 55–1400 Hz search range, an RMS floor, a confidence threshold, and clipping detection. Two consistent frames plus a short median filter reduce flicker. Silence, consonants and uncertain/overlapping target notes receive neutral guidance. New note onsets have an 80 ms settling window.
- `vocal-microphone.mjs` uses an opt-in `getUserMedia` audio stream and a 4096-sample Web Audio analyser at about 16 updates/second. It never connects microphone input to speakers. A generation token handles permission cancellation and changes during asynchronous setup. Streams, audio nodes and the microphone's separate AudioContext are released on shutdown. Requested echo cancellation is best-effort; phones may ignore processing constraints.
- Input is compared to timed MIDI melody notes on the same audible playback clock as the lyrics. The analyser's half-buffer delay is compensated; an additional user-adjustable 0–300 ms correction defaults to 80 ms. This is an adjustable estimate, not measured hardware calibration. Bluetooth routing, room noise, backing vocals/speakers, strong harmonics, vibrato, transitions and octave ambiguity can affect accuracy. It identifies a melody match, not general musical key, pronunciation or singing quality.
- Layout QA uses phone-sized browser viewports. Detector tests use generated fundamentals/harmonics/noise at 44.1/48 kHz. Browser API tests cover opt-in, no monitoring, cleanup, cancellation, denial/retry, interruptions and unavailable contexts. Playback tests cover pause/continue, lyric retry and backing-offset seek alignment. Physical iPhone Safari / Android Chrome microphone and latency testing remains necessary; do not claim these devices were tested by desktop viewport QA.

Browser APIs: [microphone permission and secure contexts](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [time-domain analysis](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getFloatTimeDomainData), [resuming audio](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume). Pitch algorithm reference: de Cheveigné & Kawahara, [YIN, a fundamental frequency estimator for speech and music](https://doi.org/10.1121/1.1458024).

No database schema, persistent volume or Railway variable changes are needed. Keep the school's existing volume and song revisions.
